**หมายเหตุ A — `spike disarm` / `bench_dispatch`:**
ทั้งคู่ **เขียน state ของ mod ได้ แต่เขียน state เกมไม่ได้**
`disarm` มีเจตนาให้ไม่ gate เพราะเป็น **เบรกฉุกเฉิน** (ปลดอาวุธได้เสมอ แม้ `AllowRemoteInput=false`)
และตามการออกแบบ S1.5-d: เมื่อตั้ง `allowRemoteInput=false` ตัว `set_pref` จะเรียก `Disarm()` ให้เอง (:428)
`bench_dispatch` เป็นเครื่องมือวัด dispatcher ของ S0 (no-op เท่านั้น)
⇒ ทั้งสองตัว **ไม่ใช่ write path ไปถึง state เกม** แต่ไม่ผ่าน `AllowRemoteInput` จึงรายงานให้ตัดสิน (ไม่เลือกเอง)

**หมายเหตุ B — `set_pref` เป็นประตูที่ไม่ถูกกันเลย:**
`set_pref key=allowRemoteInput value=true` เปิด panic switch ได้เองโดยไม่มี gate
⇒ ใครก็ตามที่ต่อ pipe ได้ (ตอน `Enabled=true` = ตอนที่ S2 ทำงาน) สามารถ **เปิดทาง** ให้ `arm/move/attack` ได้ในภายหลัง
ข้อเท็จจริงที่เกี่ยวข้อง: **`set_pref` ไม่ได้เขียน state เกมโดยตรง** และในรอบวัดนี้ **ไม่มีเครื่องมือตัวไหนเรียก `set_pref`**
(recorder = `spike status` เท่านั้น) · ระหว่างที่ `AllowRemoteInput` ถูกเปิด S2 guard จะเห็นภายใน ≤1 Hz แล้วหยุด (idle)
⇒ เสนอ (ยังไม่ทำใน stage นี้ ต้องรออนุมัติ): กัน `set_pref` ให้เปิด write path ไม่ได้ขณะ S2 active หรือย้ายไป S2a-4 (`WriteGuard` hook)

**สรุปคำตอบ:** ในบรรดาคำสั่งที่เปิดได้ตอน `DevCommands=true` —
- คำสั่งที่ **เขียน state เกม** มี 2 ตัว: `spike move`, `spike attack` — **ทั้งคู่ผ่าน `AllowRemoteInput`** (IpcServer.cs:355, :381)
- คำสั่งที่เขียนได้แต่ **ไม่ถึง state เกม**: `spike disarm` (A), `bench_dispatch` (A), `set_pref` (B), `capture start/stop`, `compat_dump`, `s1_report`
⇒ **ไม่มีคำสั่งที่เขียน state เกมได้โดยไม่ผ่าน `AllowRemoteInput`** · แต่มี 3 รายการที่ "เขียน mod-state" โดยไม่ผ่าน `AllowRemoteInput` (A/B) ซึ่งรายงานให้ผู้ใช้อนุมัติ (กติกา: หยุดและรายงาน ไม่เลือกเอง)
