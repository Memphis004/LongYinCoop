## 4. ข้อเท็จจริงที่ได้ (RUNTIME) และข้อที่ยังไม่รู้

**ได้ (RUNTIME):**
1. ยูนิตที่เดินจบจะถูกเกม**ใส่โหมดเล็งโจมตีให้เอง** (`ChangeActiveSkill(788,10)` → `ChangeNowActiveAttackSkill`) — ไม่ต้องกดอะไรเพิ่ม
2. การยืนยันโจมตี = คลิกช่องศัตรู **ครั้งเดียว** ใน state `WaitAttacking` → เกิด chain ทั้งหมดในคลิกนั้น
3. `attackComfirmed` เป็นสัญญาณชั่วคราว: true เฉพาะใน postfix ของคลิกที่ถูกยอมรับ แล้วกลับ false ที่ `BattleUnitAttackStart` → **ใช้เป็นตัวตรวจรับคำสั่งได้** (อ่านอย่างเดียว)
4. `attackRangeGridUnits` (24 ช่องที่เล็งได้) และ `damageRangeGridUnits` (9 ช่อง AoE) ถูกคำนวณ**ระหว่างการเล็ง** ไม่ใช่ตอน `ChangeNowActiveAttackSkill` (postfix ตอนนั้นยังเป็น 5/1 ค่าเก่า) และ **`RefreshAttackRange` ไม่ถูกเรียกเลย**
5. ตอนเริ่ม (`W7.start`) `attackRangeCount=5` (`8:17,7:17,9:17,7:18,9:18`) ทั้งที่ active อยู่ (6,12) → **list นี้ค้างจากยูนิตก่อน ไม่ถูกล้างตอนเปลี่ยนเทิร์น** → ห้ามใช้เป็น guard
6. `PlayBattleUnitAttack()` (IEnumerator, dump 363508) **ไม่ถูกเรียก**ในเส้นทางโจมตีปกติ — เส้นทางที่ใช้คือ `BattleUnitAttackStart` ตรง ๆ
7. ผู้โจมตีเสีย hp เอง 11.332 ภายใน `ManageDamage` เดียวกัน → ห้ามใช้ "hp ผู้โจมตีคงที่" เป็นเงื่อนไขตรวจ
8. AoE อาจครอบช่องที่ตัวผู้โจมตียืน (5,15) แต่ไม่มี `ManageDamage` เกิดขึ้นกับการครอบนั้น

**ยังไม่รู้:**
- ใครเซ็ต `attackRangeGridUnits`/`damageRangeGridUnits` ระหว่างเล็ง (ไม่ใช่ `RefreshAttackRange`; ไม่ได้ hook hover/pointer) — และถ้าเรา**ไม่มีการ hover** มาก่อน การคลิกด้วยโค้ดจะถูกยอมรับหรือไม่ (กลไก `attackComfirmed` ตรวจ membership ของ damage range หรือไม่)
- โจมตีโดย**ไม่เดินก่อน** จะเข้าโหมด `WaitAttacking` ได้อย่างไร (ยังไม่วัด — รอบนี้เดินก่อนเสมอ)
- `attackRangeCount` ที่ active ไม่ใช่ผู้เล็ง ควรเชื่อได้เมื่อไร (ยังไม่มีตัวยืนยันว่า list เป็นของ active ปัจจุบัน)
- `PlayBattleUnitAttack` ใช้ในเส้นทางไหน (AI? สกิลพิเศษ?)

## 5. ผลต่อการออกแบบคำสั่ง `spike attack` (ยังไม่เขียนโค้ด — รออนุมัติ)

- ใช้ **`BattleGridClicked(GameObject ของช่องเป้าหมาย)`** ครั้งเดียว (method + เส้นทางเดียวกับ UI ที่วัดได้) ไม่เขียน field ใด ๆ
- guard ที่จะใช้: `battleState==Fighting` · ไม่ pause · `nowActiveState==WaitAttacking` · active stableId ตรงกับผู้สั่ง · เป้าเป็นศัตรู team ต่างกัน + `unitAlive`
- **ไม่ใช้** `attackRangeCount`/`damageRange`/`turnAttacked` เป็น guard (ค้าง/ใช้ไม่ได้ตามข้อ 5 และ notes)
- ตรวจผลด้วยการอ่าน `attackComfirmed` ทันทีหลังคลิก (true = เกมรับ) — ถ้า false รายงานล้มเหลว **ไม่ retry** (arm ถูกใช้ไปแล้ว)
- ยืนยันดาเมจขั้นสุดท้ายด้วย `units[].hp` ของเป้า + `unitAlive` (ไม่ใช้ `HeroData.hp`, ไม่ใช้ `nowActiveUnitAttacked`)
