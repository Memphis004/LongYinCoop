- ช่วง ③ final pause **สั้นกว่า**โครง 55 ms (วัด 445 จาก 500) — เป็นข้อเท็จจริงจากไฟล์ที่**ไม่**อธิบายได้ด้วย

- **HYPOTHESIS (ห้ามใช้ตัดสิน):** ส่วนเกินของช่วง ① อาจมาจากแอนิเมชัน/เสียง/ช่วง freeze ของเกมรอบเริ่มงาน —
  **ไม่มีหลักฐานจากไฟล์ NDJSON** (ไฟล์ไม่มี event แอนิเมชัน) — static (time-static-notes §2.4) ระบุว่า

  อยู่ใน segment ไหนยังระบุไม่ได้จากไฟล์เดียว** (รอรูปแบบจาก A3-r1 N=10 ซึ่งมี 13 pause_end — ข้อมูลจะแยก
  ช่วงได้เอง) · ตามมติ [CRITERIA]: ส่วนเกินที่อธิบายไม่ได้รายงานเป็นค่าแยก ไม่ใช้ตัดสินฟอร์ม

## 3) นิยาม T ของ analyzer เทียบค่าวัดเดิม ~12.5 s (OBSERVED จากเอกสาร — อ้างบรรทัดจริง)

- **analyzer** (`tools/time_v2a_analyze.py:74`): `t = (t_end − t_start)/1000` โดย t_start = event `work_start`
  (เฟรมแรกที่ sampler เห็น `working==1` — หลัง StartWorking เขียน field ครบ รวม `leftPauseTime=initial`)
  และ t_end = `work_end` (working 1→0 หลังกิ่งจบงาน) ⇒ **รวม initial pause + วันทั้งหมด + final 2×pause**
- **ค่าวัดเดิม ~12.5 s** (`area-notes.md` P1-5 บรรทัด 104–118 — แถว "อัตราเวลา" บรรทัด 109): ปรากฏเป็น
  "`dayTime=1`, `pauseTime=0.25` ⇒ 10 วัน ≈ 12.5 วิ" — **ผูกกับเลขคณิต 10×(1+0.25) และไม่มีบันทึกจุดเริ่ม/จบ
  การวัด (timestamp หรือนิยาม anchor) ใด ๆ ใน P1-5** · `time-plan-draft.md` H1 (บรรทัด 545–551) สรุปเรื่องนี้ไว้แล้ว:
  "ไม่พบข้อความใดนิยามว่า 'n=1' … แผนนี้จึงไม่ตีความ · ข้อเท็จจริงที่ยืนยันได้มีเพียง: ค่าประมาณ 12.5 วินาทีมาจาก
  กรณี 10 วัน … ระบุ '10 วัน ≈ 12.5 วิ' ตรงตัว"
- **ต่างกันอย่างไร:** นิยามของ analyzer ตรงกับนิยามที่แผนกำหนด**สำหรับ V2** เอง — §E.1 (บรรทัด 396–397)
  "เวลา wall-clock รวม | E1 → E4" โดย E1 = StartWorking entry, E4 = กิ่งจบงาน 0x9CBCC7 ⇒ รวม initial pause
  (โครงสร้างแบบ FORM2) · ส่วนตัวเลขเดิม 12.5 = FORM1 ทางเลขคณิต (`N×(D+P)` — **ไม่รวม** initial pause) และ
  **ไม่เคยมีนิยาม anchor บันทึกไว้** ⇒ เทียบกันตรง ๆ ไม่ได้ และแผนห้ามใช้ค่าเดิมตัดสินโมเดลอยู่แล้ว (B.6 บรรทัด
  169–172, H.2) — การวัดของ V2 จึงต้องตัดสินด้วย**ความชัน/ตัดแกนจากหลาย N** ตาม [CRITERIA] ไม่ใช่เทียบ 12.5
- ข้อเท็จจริงเสริมจาก P1-5 (บรรทัด 117 — รอบ hook A แบบ **skip**): day-tick ห่างกัน 0.75–2.1 วิ รวม 10.5 วิ —
  เป็นข้อมูล skip (k≈0.5) ไม่ใช่ normal — อ้างได้แค่ว่า hook วัดเป็นช่วงระหว่าง day-tick ไม่ใช่ work_start→work_end
