## 5. ข้อบกพร่อง/หนี้ทางเทคนิคที่ยังเปิด (RUNTIME/โค้ด)

1. `TARGET_DEAD` guard ใช้ `HeroData.dead` (ไม่ใช่ธงตายในศึก) → ตายด้าน (ดู §4.2)
2. `alive` ใน `stateHash` อิง `!HeroData.dead` ⇒ hash ไม่สะท้อนการตาย (และไม่ไวต่อดาเมจ — W5)
3. `attackRangeGridUnits` ไม่มี prefire guard: คำสั่งยิงนอกระยะจะคลิกแล้วรอเกมปฏิเสธ = เสีย arm เปล่า (`OUT_OF_RANGE` ต้องรอผลหลังคลิก)
4. `spike status` บอกแค่ *จำนวน* ช่องโจมตี ไม่บอก *ช่องไหน* → mod เลือกเป้าเองไม่ได้
5. เส้นทาง fail ของ spike ไม่เขียน log ฝั่ง mod (หลักฐานเชิงลบอยู่ที่ JSON ฝั่ง CLI อย่างเดียว)
6. guard `ALREADY_USED` ฝั่ง mod ยัง NOT-RUN (client ตัดก่อนถึง mod — เลื่อนมา S1.5f แล้วแต่ยังไม่ได้ทดสอบเคสนี้)
7. `save-split.py verify` ใช้ *ก่อน* restore เท่านั้น — รันหลัง restore จะ FAIL ด้วยเหตุผลการออกแบบ (ควรมี `--post-restore`)
8. พฤติกรรมการจบเทิร์นไม่คงที่ (เกมสลับเทิร์นเอง 2/10 ครั้งใน S1.5-d) และยูนิต `0:4` ย้ายเองระหว่างรอบ 11→12 — ยังไม่มีคำอธิบาย (ผลต่อ S3: ต้องไม่ assume ว่าเทิร์นจะจบเอง)
