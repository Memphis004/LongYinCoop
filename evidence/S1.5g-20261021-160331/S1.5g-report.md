## 3. เหตุผลที่ Phase B เป็น NOT-RUN (ตรง ๆ)

- เข้าเกณฑ์ "600 s" เฉพาะการนับแบบ wall-clock ลบ pause (2,455 s) ซึ่ง **รวมช่วงที่ผู้ใช้ไม่ได้เล่น 33 นาที**
- ช่วงที่เล่นจริง = 18:28:24 → 18:36:28 หัก pause 5.4 s และเมนู Esc 67.8 s = **411.1 s (6.9 นาที)** < 600 s
- ผู้ใช้ไม่ได้เล่นต่อหลัง 18:36:28 เพราะหยุดคุยกับผม (ไม่ใช่ความผิดของเกม) — ช่วงนั้น `WaitPlayerInput` ค้างที่ turn 0 โดยดีไซน์
- ตามกติกา "ห้ามตีความหลักฐานที่ไม่ครบเป็น PASS" ⇒ **NOT-RUN** ไม่ใช่ FAIL ของเกม และไม่ใช่ PASS

## 4. ข้อเท็จจริงใหม่ที่ต้องถือต่อ (RUNTIME)

1. **เมนู Esc หยุด sim แต่ไม่ตั้ง `battlePaused`**: 67.8 s ที่ `battleTime`/`turnIndex` นิ่ง (`Attacking`→`Finish`) ขณะ `paused=false`, `timeScale=1`, `battleTimeScale=1`, `frame` เดิน ≈128 fps ⇒ **ห้ามใช้ `battlePaused` หรือ `Time.timeScale` เป็นตัวตัดสินว่า "เกมเดินอยู่"** ต้องดู `battleTime`/`turnIndex`/state
2. **ปุ่ม "หยุด" ของเกม pause ได้ทุก state ที่ทดสอบ** (Rest/Moving/WaitMoving/WaitAttacking/Attacking/None/Finish) — 16/16 รอบ clock นิ่งสนิท และ `timeScale` ยังเป็น 1 (ไม่ได้ทำผ่าน timeScale)
3. **ไม่มีคำสั่ง `spike pause` ใน build นี้** — pause ที่ทดสอบคือ UI ของเกม (ไม่ใช่ code path ของ mod) ⇒ หลักฐาน pause เก่า (`f0cf25994008`, `c45ac7b53ae2`) ยังใช้แทนกันไม่ได้
4. **จบศึก/เข้าศึกใหม่ทำงานปกติ** ใน build นี้ระหว่างที่มี sampler + hook ทำงาน: 18:35:03 จบ, 18:36:08/18:36:27 เข้าศึกใหม่
5. **IPC/sampler ไม่ block เกม**: sample 30,510 ครั้งใน 51 นาที, gap สูงสุด 0.60 s, fail 5 ครั้งเฉพาะจุดเปลี่ยนฉาก/ปิดเกม

4. ไม่ได้วัดว่าหลังเมนู Esc ปิดแล้ว clock เดินต่อทันทีหรือมีดีเลย์ (ภาพรวม resumed=true แต่ไม่ได้วัดระดับ ms)
